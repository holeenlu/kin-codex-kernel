# v0.4.5 — 修正服務等級的出站路由

## 新增功能

- 本版無此項。

## 優化

- 已逐筆處置官方 Codex main 的 65 筆增量，將同步基線推進至 `6aaf2a86`。本次查詢的 CPR main 為 `037cbcd6`，與上版相同。各筆處置與相容性取捨見本版 `docs/sync/2026-11-24-main.md`。

## Bug 修正

- HTTP POST 和 WebSocket 握手都會使用請求本體的模型與 `service_tier` 組成 `x-codex-routing-hint`。例如請求 `priority` 時，路由提示會附上 `tier=priority`。省略等級或使用 `auto`、`standard`、`default` 時只帶模型。上游回應仍是判斷實際服務等級的依據。
- 同一會話從 `priority` 切到 `ultrafast` 時會另開握手相符的 WebSocket，切回原等級時可重用仍可用的原連線。

## 升級影響

- v0.4.4 可直接升級。ABI 1／2 與設定格式相容，Linux 執行檔要求 glibc 2.34 或以上。HTTP 與 WebSocket 繼續把事件序號與推理項目的加密欄位交給控制面。
- vm2api 維護者可在其倉庫執行 `python3 scripts/release/sync_tap_payload.py --apply`，驗證本版附件並更新 `deploy/payload.json`。部署對應的 vm2api 版本後，逐槽核對核心版本、能力與健康狀態。

## 驗證結果

- 升版前受測 Git 樹為 `77f0c6a9`，Rust 1.99.1 的 fmt、Clippy、163 項工作區測試與 cargo-deny 四類檢查通過。兩個服務等級回歸都在 v0.4.4 重現並在本版通過。HTTP 與 WebSocket 測試也核對了原始串流欄位。
- 升版前候選的 Linux amd64、arm64 建置均通過 glibc 2.34 檢查。以候選 amd64、vm2api `c04de132` 與四份官方 CLI 基準在斷網環境驗證 ABI 1／2，87 項通過、0 失敗，11 個未提供測試目標時使用的占位案例略過。
- 以官方 0.171.0 Linux amd64 TUI 對本機測試後端完成兩個斷網回合。WebSocket 握手與拒絕握手後的 HTTP POST 都收到 `model=gpt-5.5;tier=priority`。這兩次實錄使用同一正式版 Linux amd64 CLI。
- 私有狀態下的同步提交 CI 因 GitHub 帳務或支出上限未能啟動。正式標籤的品質關卡與建置結果見本版 GitHub Actions 紀錄。
