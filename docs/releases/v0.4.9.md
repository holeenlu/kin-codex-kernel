# v0.4.9 共享核心容量控制、憑據交接與 WebSocket 重送修正

## 新增功能

- ABI 1 與 ABI 2 可透過 `ingress_limits` 限制同時處理的業務請求、請求本體總量與圖片請求數。預設分別為 128 筆、256 MiB、4 筆。額滿時回傳 `503 kernel_busy`，健康檢查與取消仍可使用。
- 共享模式的控制面可讀取 `registry_revision` 並在全量對帳時帶回 `expected_registry_revision`，避免晚到的清單覆寫較新的帳號異動。WebSocket 串流的內部收據也可分別查看首個生成事件前等待上游資料與等待下游再次取幀的時間。

## 優化

- WebSocket 續接重用首幀的解析結果。單槽 packed 請求依 gzip 實際展開大小占用程序預算，解碼名額在進入推理前釋放；一般與 packed 請求共用後續的 Responses 處理。
- 帳號登錄把上游執行環境的建構移出寫鎖，帳號列表可平行讀取憑據代次。帳號操作等候 HTTP 標頭與逐塊讀取本體時均套用閒置期限。

## Bug 修正

- WebSocket 寫出生成請求後，若連線關閉且無法判定是否送達，核心會回報送達不明並停止自動重送，避免重複生成。相同代理的額外握手及 HTTP 降級共用重試預算。
- 同時進行的推理與帳號操作若使用相同的 `request_id`，後到者回 409，避免取消錯誤的請求。packed 入口分別回報基底缺失、格式錯誤與大小超限，閘道可據以判斷何時能安全補送。
- 跨程序換票與匯入共用憑據寫入鎖。換票成功但落盤失敗時保留新票並優先補寫；遲到的舊票失敗不會蓋掉新憑據的狀態。換票失敗即使正文中斷，仍以已收到的 HTTP 狀態判定是否需要重新授權。

## 升級影響

- **共享模式先升控制面，再升核心。** 憑據匯入與強制刷新須帶派發時的 `env_generation`；缺值回 400，代次不符回 409。兩種 ABI 的呼叫端都須為每次派發配置獨立的 `request_id`。
- 沿用固定 Unix socket 時，先排空舊核心並等它退出，再啟動新版。共享憑據的寫入者須使用同一路徑及支援檔案鎖的檔案系統；後續交接前確認換票完成且 `credential_writeback_pending` 為 false。
- 下游依部署架構更新核心載荷釘選與 SHA-256。閘道讀取 packed 回應時，須同時收到 409、`x-kin-uds-miss: 1` 與 `x-kin-upstream-sent: 0` 才能因基底缺失補送；寫入中斷且未取得收據時，按送達不明處理。

## 驗證結果

- 本版功能整合時已以雙程序 Unix socket 驗證共用憑據只向上游換票一次。在圖片名額設為一筆時，八筆額外圖片請求均收到 503 與未送出收據，健康及用量查詢仍成功。
- 發版前以 Linux arm64、Rust 1.99.1 執行 `cargo test --locked --workspace`，197 項通過，失敗及略過均為零。`cargo fmt --all -- --check` 通過。
