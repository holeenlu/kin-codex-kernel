# v0.4.4 — 終態即時回傳與 WebSocket 連線可靠性

## 新增功能

- 本版無此項。

## 優化

- 閒置 WebSocket 持續處理 Ping/Pong，包括 Pong 寫入背壓；下一輪仍可依原帳號、會話及回應歸屬重用連線，不必等新請求才驅動保活。既有 TTL、池容量與帳號隔離保持不變。
- 整理 TLS 與壓縮相依：native-tls 升至 0.2.18，停用未使用的 aws-lc-rs ring 相容介面，zstd 統一至 0.14.4，cookie 升至 0.18.3。HTTP 的 OpenSSL、WebSocket 的 rustls／aws-lc provider 與官方身分目標保持原設定；zstd 出站位元組已與舊串流編碼比對。
- 分開維護原始碼同步進度與 CLI 實錄基準。本版已處置 CPR main 至 `037cbcd6` 的 4 筆增量，以及官方 Codex main 至 `93f105d2` 的 252 筆增量；控制面選號、計價及結算仍由 vm2api 負責。完整處置見本版 `docs/sync/2026-11-23-main.md`。

## Bug 修正

- 非串流 HTTP 收到完整 SSE 終態後立即回傳。上游已送出完成、policy、spend-limit 或容量錯誤卻保持連線開啟時，不再持續等待 EOF；原始 JSON 與用量保持不變。
- 上游錯誤的 `error.headers.Retry-After` 現在可不分大小寫解析，並優先於外層事件 headers；實際 HTTP header 仍有最高優先權，既有安全字元與長度限制保持。
- `response.interrupt` 寫入失敗時，先交付已到達的終態與原始用量，避免被傳輸錯誤蓋掉。失敗連線不回池，送出狀態不明仍保留為不明，不因此允許重播。
- 更新官方 WebSocket 傳輸分支的日誌修正，送出訊框的 trace 記錄改為類型、結束旗標及長度，避免記錄請求 payload。握手、壓縮與 TLS 行為不變。

## 升級影響

- v0.4.3 可直接升級。ABI 1、ABI 2、設定格式及能力名稱保持相容，沒有資料庫遷移。Linux 產物仍要求 glibc 2.34 或以上。
- Tap 執行檔版本改為 0.4.4；出站 User-Agent 與 TLS 實錄目標仍是官方正式版 Codex 0.171.0。main 的 exclude 預設與 Orca 別名正規化仍保留明示差異，不宣稱正式版實錄涵蓋全部 main 分支。
- 本版以正式版發布並設為 Latest。倉庫僅於建置與發布期間公開，核對正文及附件後即恢復私有；授權帳號仍可取得附件。
- vm2api 操作者須依 `scripts/release/sync_tap_payload.py` 與 payload 規則接入本版附件，核對雜湊及執行中的核心版本、能力與逐槽健康。發布 Tap 不會自動更新 vm2api 載荷或部署生產。

## 驗證結果

- 發布前已核對，升版前的程式碼、第三方相依、features 與四份實錄基準，均與已驗證程式樹 `e37d0b9737910890e85898b2393ef4d567239286` 一致。本次新增版本欄位及本版說明，沿用有效業務回歸證據；正式標籤的建置結果由後附 GitHub Actions 紀錄提供。
- Rust 1.99.1 的 fmt、Clippy 全 workspace／all-targets／`-D warnings`、161 項 workspace 測試與 cargo-deny advisories／bans／licenses／sources 檢查通過。回歸涵蓋碎片化多行 CRLF SSE、不關閉上游的終態、閒置 Pong 背壓、續接歸屬、寫入失敗後的終態用量與 zstd 編碼邊界。
- 升版前候選 Linux amd64／arm64 release 均建置成功，glibc 檢查均為 2.34。使用候選 amd64 二進位、vm2api `bbee78c8` 鎖版輸入及四份 CLI 實錄基準，在斷網 Linux 容器中執行契約測試：87 通過、0 失敗，11 個略過僅為未提供測試目標時使用的占位案例，涵蓋 ABI 1、ABI 2、傳輸、身分、換票及帳號操作。
- 私有狀態下的先前 main CI 因 GitHub 帳務／支出上限未啟動，不列為通過。本輪未做真實供應商推理、生產部署或 arm64 官方 CLI 實錄；不以 arm64 編譯成功代替該平台的出站實錄驗收。
