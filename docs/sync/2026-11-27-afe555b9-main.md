### WebSocket 與平台設定

- **握手 ETag**。Kin 將 `x-models-etag` 存在實體 socket 上。預熱保留它，第一次獲接受的生成用 `take()` 交付。重用時沒有舊 ETag，新握手則有自己的值。既有整合案例以兩條連線依序斷言「預熱無值、首輪 catalog-0、次輪無值、新線 catalog-1」。[實作](../../crates/upstream/src/websocket.rs) · [整合測試](../../crates/api/tests/responses_websocket.rs)
- **事件欄位**。CPR 接受 `x-codex-exclude` 和 `x-codex-exclude-stream-fields`，因此將兩者的所有值納入連線鍵。核對 TapModels 與 MaxModels 本機提交 `2b47326e` 的 `src/lib/protocol/handle-codex.mjs`，兩者的入口白名單和 Kin 的 HTTP／WS 標頭表均省略這兩個名稱。Kin 的連線鍵以長度分隔最終握手標頭，保留重複值與次序，對逐輪追蹤欄位另行正規化。現有 HTTP 與 WS 案例在請求含串流排除標頭時仍期望原始序號及加密內容。[標頭組裝](../../crates/upstream/src/headers.rs) · [HTTP 測試](../../crates/api/tests/responses_http.rs) · [WS 測試](../../crates/api/tests/responses_websocket.rs)
- **池與駐留地**。CPR 熱更新每輪等待及同時建連數，既有連線沿用建立時的壽命設定。Kin 由呼叫方逐請求提供 `ws_limits`，核心另限制閒置保留 240 秒、全池 256 條、每鍵 8 條。兩種設定的作用域不同。官方凍結版本的 `codex-rs/model-provider-info/src/lib.rs` 依受管設定套用駐留要求，Kin 的四份出站基準均無駐留標頭。直接複製 CPR 的 `us` 預設會改變兩個品牌的出站請求。[傳輸實作](../../crates/upstream/src/websocket.rs) · [實錄目標](../../fidelity/README.md)
