## 與核心行為的交集

- CPR 的 `ResponseControl::receive` 在從未綁定連線時等待，已綁定的弱引用失效時則通知閘道，讓仍連線的下游客戶端重連。Kin 的 [WS 回合](../../crates/upstream/src/websocket.rs) 在終態結束該次 ABI 回應，可將上游連線留給下一輪。[中斷入口](../../crates/api/src/routes.rs) 只接受指定在途請求的控制指令，找不到可用通道時回 HTTP 409。
- CPR 拆分 OpenAI 的 HTTP client、模型目錄及串流模組。既有 OAuth 身分鍵函式從 `credential/types.rs` 搬到 `request_identity.rs`，輸入仍為本地帳號、上游使用者及上游帳號。WS 搜尋宣告重連測試也可在父提交找到。新增的 Antigravity 傳輸使用另一供應商，計價及跨帳號排程由控制面負責。
- 官方僅對符合條件的自訂 HTTPS gateway 自動探測目錄，失敗時可回退至 CLI 內建選單。Kin 的 [模型目錄操作](../../crates/upstream/src/ops.rs) 代發指定 ChatGPT 帳號的請求，保留上游結果。API 工作負載身分修正使用服務帳號、組織及專案辨識憑據所有者。語音相關變更在 Realtime 端點，與 Responses 的 WebSocket 分屬不同協定。
