## 採用的行為與保留差異

- **HTTP 終態：** 非串流請求收到完整 SSE 終態即回傳，避免上游已完成卻未關閉連線時持續等 EOF。回歸以 7-byte chunk、多行 CRLF SSE 及持續開啟的連線，覆蓋正常用量、三種 spend-limit、bio／cyber、容量與過載錯誤；回應 JSON 保持原樣。串流路徑仍逐 chunk 轉送，不加入 CLI 的顯示錯誤投影或重試。
- **錯誤收據：** WS 首事件的 `error.headers.Retry-After` 以不分大小寫方式解析；實際 HTTP header、巢狀事件 header、外層事件 header、既有 `retry_after` 依序優先。維持長度與安全字元檢查，不創造重試次數、用量或送出事實。
- **閒置 WS：** 池內連線持續處理 Ping/Pong，背景讀取不持有池鎖等待 I/O。借出時交還同一 socket，保留 owner、帳號 runtime、握手語義、240 秒 TTL、全池及每鍵上限。淘汰與取消會終止背景工作，名額仍隨池項目同步歸還。背壓測試使用 32-byte 管道與 120-byte Ping，並驗證下一輪重用及淘汰。
- **中斷寫入：** `response.interrupt` 使用既有雙向上傳函式；寫入失敗仍先交付已就緒的終態與原始用量，該連線不再入池。回歸只在 BrokenPipe 後使終態可讀，確保測到失敗分支。`response.create` 既有 1 MiB／32 事件緩衝及分片公平性保留，不引入官方 CLI 單會話的整套 pump。
- **相依：** cookie 升為 0.18.3。官方 tokio-tungstenite 升為 `7a920470d62138955446b64220c7609e46ad770e`，tungstenite 升為 `e19950ef7828cb311e6d51a6bedcebf0192e055c`；完整 fork 差異只改送出訊框的 trace 日誌，不記錄 payload，另加來源回歸，握手／壓縮／TLS 未變。Tap 原已具備 url 2.5.9／form_urlencoded 1.2.3。沒有複製來源鎖檔或變更 TLS provider；授權來源維持 NOTICE 與 cargo-deny 白名單。
